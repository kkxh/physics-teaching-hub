# 工程约定（踩坑清单）

这份文件记录「写代码时默认就得这么做」的约定，来源是实际踩过的坑——包括上游一次 P0 修复
提炼出的通用教训。每条都写清三件事：**约定做什么、为什么、在哪个阶段生效**。

只写通用工程规则：不含任何真实数据、学校信息、上游文件内容或本机路径。
配合 [MIGRATION_LEDGER.md](MIGRATION_LEDGER.md) 的「预吸收清单」使用：写代码时按本文件执行，
搬运日按那张表核对。

## 1. 身份：一律用 ID 关联，姓名只用于显示

- 约定：跨表关联、导入匹配、跟进记录关联，都以 `student_id` 为准；姓名匹配到多条时必须报错，
  并要求调用方用 ID 指定，**禁止「取第一条」**；写记录时姓名、班级按 ID 从主表读，
  不信任调用方传进来的冗余字段。
- 为什么：同名、改名、转班都会让姓名匹配悄悄挂错人，而且错得没有痕迹、事后很难查。
- 生效阶段：Phase 2（数据层、导入器、分析输出）。
- 怎么验：单测覆盖「同名两条 → 报错」「ID 不存在 → 拒绝写入并回滚」。

## 2. 时间：入库统一 UTC，展示才转时区

- 约定：数据库里的时间列一律存 UTC；时区只在展示与报告层用配置里的 `project.timezone` 转一次。
- 为什么：混用本地时间与 UTC，会让「同一天」「第几教学周」在换机器或跨时区时对不上。
- 生效阶段：P1.6（临时 schema 起生效）。
- 怎么验：schema 默认值里不出现本地时区函数；测试断言落库值是 UTC。

## 3. 数据库：连接、外键与 schema 完整性

- 每条连接显式 `PRAGMA foreign_keys = ON`——SQLite 默认关闭，不开外键约束等于没有约束。
- 判断 schema 是否就绪，要用「建库脚本声明的**完整表清单**」，不要只抽查几张哨兵表，
  否则残缺 schema 会被误判成「已经建好」。
- 「已初始化」这类缓存按**数据库路径**记忆，不要用一个全局布尔：换库之后全局标记会骗人。
- 初始化与迁移都要幂等：重复执行不报错、不产生重复行。
- 生效阶段：P1.6 起。

## 4. 事务：一组改动要么全成、要么全退

- 约定：跨多张表的写入，或「先收束旧记录、再写新记录」这类操作，放进同一个事务，异常整体回滚；
  不要留下「旧的改了、新的没写」的中间状态。
- 需要预览（dry-run）的操作，预览与真正执行必须走同一套查询条件，否则预览会骗人。
- 生效阶段：Phase 2（数据层）。

## 5. 输入与查询：不拼字符串，不把用户输入当通配符

- 约定：SQL 一律参数化，不做字符串拼接；把用户输入放进 `LIKE` 时，要么转义 `%` 和 `_`，
  要么改成字面前缀比较（按长度截取比较），避免用户输入的 `%` 意外扩大匹配范围。
- 生效阶段：Phase 2 起。

## 6. 空值与 0：判空别用真值判断

- 约定：分数、人数、序号、编号这类数值判「有没有值」用 `is None`，不要写 `if not x`——
  0 是合法值，用真值判断会把 0 分当成「没有分数」丢掉。
- 生效阶段：P1.5（演示数据）、P1.6（导入）。

## 7. 对外调用：HTTP 200 不等于成功

- 约定：调用外部服务（推送、外部模型）要校验业务错误码，显式设置超时；失败必须让调用方感知，
  绝不能把「其实没成功」记成「已发送/已写入」。
- 生效阶段：Phase 2 起。

## 8. 本地服务：只绑本机，CORS 不用通配符

- 约定：本地 API 只绑定 `127.0.0.1`；CORS 只回固定的本机 Origin（含实际端口），
  并带上 `Vary: Origin`；不写 `Access-Control-Allow-Origin: *`。
- 为什么：本机服务加上通配符 CORS，等于让任意网页都能读到本地教学数据。
- 生效阶段：Phase 2（本地 API 与看板前端）。

## 9. 隐私：默认脱敏，外发要显式授权

- 约定：任何把数据送出本机的动作（外部模型、推送）默认脱敏——姓名换成代号、不带班级、
  只发聚合统计；要带原始明细，必须是显式开关，默认关闭。
- 写入类操作走「**预览 → 确认 → 单事务写入**」，失败回滚。
- 对应本仓库硬规则：[AGENTS.md](../AGENTS.md) 第 3 节与 [PRIVACY.md](PRIVACY.md)。
- 生效阶段：Phase 2 起。

## 10. 回归检查：绝不碰真实数据

- 约定：测试、冒烟、回归脚本一律用临时库或临时目录；文档里的示例命令也不要出现真实数据路径。
- 现状：本仓库已经满足——测试与 CI 只用 `tmp` 与虚构演示数据（见 `seed_demo_data.py`）。

## 11. 数据层：显式传入连接或路径，模块内不写死数据库位置

- 约定：所有数据访问函数接收显式的 `connection` 或 `db_path`，由调用方（命令层）决定用哪个库；
  模块内部不自行拼接或写死数据库位置。
- 为什么：写死位置会让测试、回归和脚本无法安全指向临时库——上游正是因此出现过
  「回归跑在真实库上」和「以为写了、其实写到别处」两类问题。
- 生效阶段：P2.0 的 `db.py` 起，之后每个模块都用它。
- 怎么验：守护测试断言除 `db.py` 外不出现 `sqlite3.connect(`；每个写操作模块都有
  「`--db` 指向临时库时默认库不变」的回归测试。
